# LiveSub 程式架構說明

這份文件說明「程式是怎麼運作的」以及「每個檔案負責什麼」，給想看懂或修改程式的人閱讀。
只想使用程式的話，請看 [使用說明書.md](使用說明書.md)。

> 每個程式檔的開頭都有一段說明（docstring），函式內部也有中文註解。
> 建議搭配本文件，從 [app.py](../src/livesub/app.py) → [pipeline.py](../src/livesub/pipeline.py) 開始讀。

---

## 1. 一句話的旅程

講者說了一句 "Welcome to today's meeting."，程式內部依序發生：

| 步驟 | 誰負責 | 做了什麼 | 資料變成 |
|---|---|---|---|
| ① 收音 | `audio/capture.py` | 每 50 毫秒從音效卡取一小塊聲音，轉成 16 kHz 單聲道 | 一小塊音訊 |
| ② 切句 | `audio/segmenter.py` | 用 VAD 判斷是不是人在說話，講者停頓 0.6 秒就算一句結束 | `Utterance`（一句的音訊） |
| ③ 辨識 | `asr/cloud_openai.py` | 把這句音訊包成 WAV 檔上傳 Groq／OpenAI，取回文字與語言 | `Transcription`（原文） |
| ④ 過濾 | `asr/filters.py` | 丟掉 Whisper 的幻覺句（例如 "Thank you for watching"） | — |
| ⑤ 翻譯 | `translation/claude.py` | 把原文＋前幾句＋術語送給 Claude，取回中文 | 譯文 |
| ⑥ 台灣用語 | `translation/base.py` | OpenCC 把殘留的大陸用語轉成台灣用語 | — |
| ⑦ 記帳 | `core/budget.py` | 依單價累加本月花費，超過預算就停止雲端請求 | — |
| ⑧ 顯示 | `ui/overlay.py` | 在螢幕上畫出原文（小字）＋譯文（大字） | `SubtitleEvent` |
| ⑨ 存檔 | `output/transcript.py` | 寫入 `subtitles.srt`、`transcript.txt`、`transcript.jsonl` | — |

從講者停頓到中文出現，通常約 1～2 秒，主要花在步驟 ③ 和 ⑤ 的網路請求。

## 2. 執行緒架構

辨識與翻譯都要等網路回應，一次 0.5～2 秒。如果全部在同一個執行緒做，等待期間就收不到新的聲音，
所以程式拆成多個執行緒，彼此用**佇列**（queue，像輸送帶）傳遞資料：

```
 ┌───────────────┐   音訊塊    ┌───────────┐   一句音訊   ┌─────────┐   原文    ┌─────────────┐
 │ audio-capture │ ─────────► │ segmenter │ ──────────► │   asr   │ ───────► │  translate  │
 │  （收音）      │  _audio_q  │ （切句）   │ _final_utts │（辨識）  │_final_trs│  （翻譯）    │
 └───────────────┘            └───────────┘             └─────────┘          └──────┬──────┘
                                                                                    │ Qt 訊號
                                                                                    ▼
                                                           ┌──────────────────────────────────┐
                                                           │ 主執行緒（UI）：字幕浮層、系統匣  │
                                                           └──────────────────────────────────┘
```

| 執行緒 | 程式位置 | 工作 |
|---|---|---|
| 主執行緒 | `app.py`、`ui/` | 畫面、選單、設定視窗（只有它能改畫面） |
| `bootstrap` | `Pipeline._bootstrap` | 啟動時載入辨識器，然後啟動下面四個執行緒 |
| `audio-capture` | `AudioCapture._run` | 收音 |
| `segmenter` | `Pipeline._segment_loop` | 切句 |
| `asr` | `Pipeline._asr_loop` | 語音辨識 |
| `translate` | `Pipeline._translate_loop` | 翻譯、寫逐字稿 |

**為什麼字幕不會越來越慢？**
- 定稿的佇列有長度上限，塞車時丟掉最舊的一句，畫面會顯示「辨識跟不上」。
- 中間結果用「只保留最新一筆」的信箱（`LatestOnly`），舊的直接被覆蓋，所以不會累積延遲。

**背景執行緒怎麼更新畫面？**
Qt 規定只有主執行緒能改畫面。背景執行緒呼叫 `UiBridge.event.emit(...)` 發出訊號，
Qt 會把它排進主執行緒的事件佇列，再由主執行緒呼叫 `SubtitleOverlay.on_event()`。

## 3. 資料夾與檔案說明

```
live-subtitle/
├─ src/livesub/              程式本體（Python 套件）
├─ tests/                    自動測試（不需音效卡、網路）
├─ scripts/                  PowerShell 腳本：安裝、執行、打包
├─ packaging/                PyInstaller 打包設定
├─ docs/                     說明文件（本檔、使用說明書）
├─ config.example.toml       設定檔範本（第一次執行會複製成 config.toml）
├─ glossary.example.csv      術語表範本（會複製成 glossary.csv）
├─ requirements*.txt         需要安裝的套件清單
└─ pyproject.toml            專案資訊與 pytest／ruff 設定
```

執行後才會出現（不進 Git）：`.venv/`（虛擬環境）、`config.toml`、`glossary.csv`、
`usage_ledger.json`（本月花費）、`logs/`、`transcripts/`、`models/`（本機 Whisper 模型）。

### 3-1. 進入點

| 檔案 | 說明 |
|---|---|
| [`__main__.py`](../src/livesub/__main__.py) | `python -m livesub` 的入口，只呼叫 `app.main()` |
| [`app.py`](../src/livesub/app.py) | **主流程**：解析命令列參數 → 讀設定 → 建立所有元件 → 建立畫面 → 啟動管線 → 進入事件迴圈。也負責「設定存檔後重新啟動」 |
| [`pipeline.py`](../src/livesub/pipeline.py) | **管線核心**：建立佇列與背景執行緒，把收音、切句、辨識、翻譯串起來；處理暫停、預算檢查、中間結果節流 |

### 3-2. `config/` 設定

| 檔案 | 說明 |
|---|---|
| [`schema.py`](../src/livesub/config/schema.py) | 設定的資料結構。每個 class 對應 `config.toml` 的一個 `[區段]`，欄位就是設定名稱與預設值，`__post_init__` 檢查數值是否合理 |
| [`loader.py`](../src/livesub/config/loader.py) | 讀取 `config.toml` → `AppConfig`；拼錯的設定名稱會直接報錯；自動轉換舊版格式；路徑與金鑰小工具 |
| [`writer.py`](../src/livesub/config/writer.py) | 設定視窗存檔用：只改有變動的值，保留檔案裡的註解與排版；先驗證再寫入，寫到一半當機也不會壞檔 |
| [`user_env.py`](../src/livesub/config/user_env.py) | 讀寫 Windows 使用者環境變數（API 金鑰），等同 `setx`；啟動時補讀登錄檔，存完金鑰不必重開終端機 |

### 3-3. `audio/` 收音與切句

| 檔案 | 說明 |
|---|---|
| [`capture.py`](../src/livesub/audio/capture.py) | 用 WASAPI loopback 錄下喇叭的聲音（或麥克風、或兩者混音），轉成 16 kHz 單聲道；裝置出錯自動重試。`Mixer` 負責「系統聲音＋麥克風」混音 |
| [`segmenter.py`](../src/livesub/audio/segmenter.py) | **切句狀態機**：每 30 毫秒問 VAD「是不是人聲」，決定一句的開始與結束；句子進行中定期輸出快照（中間結果）；處理 loopback 沒聲音時不送資料的斷流 |

### 3-4. `asr/` 語音辨識（聲音 → 文字）

| 檔案 | 說明 |
|---|---|
| [`base.py`](../src/livesub/asr/base.py) | 辨識器介面 `Transcriber`；從文字判斷語言（假名→日、諺文→韓…）；`LanguageTracker` 處理「短句沿用上一句語言」 |
| [`cloud_openai.py`](../src/livesub/asr/cloud_openai.py) | 雲端辨識：把音訊包成 WAV 上傳 OpenAI 相容 API（OpenAI、Groq），解析結果並記帳 |
| [`local_whisper.py`](../src/livesub/asr/local_whisper.py) | 本機辨識：faster-whisper，GPU 失敗自動退回 CPU 與小模型 |
| [`filters.py`](../src/livesub/asr/filters.py) | 過濾 Whisper 幻覺（"Thank you for watching"、重複字串等） |
| [`gpu.py`](../src/livesub/asr/gpu.py) | 讓 Windows 找到 pip 安裝的 NVIDIA CUDA DLL |
| [`registry.py`](../src/livesub/asr/registry.py) | 依 `asr.engine`（cloud／local）建立對應的辨識器 |

### 3-5. `translation/` 翻譯（原文 → 繁體中文）

| 檔案 | 說明 |
|---|---|
| [`base.py`](../src/livesub/translation/base.py) | 翻譯器介面 `Translator`；**翻譯提示詞**（規則都寫在這裡）；前文記憶 `ContextHistory`；OpenCC 台灣用語轉換；清掉模型多餘的輸出 |
| [`claude.py`](../src/livesub/translation/claude.py) | 用 Anthropic 官方 SDK 呼叫 Claude；錯誤訊息中文化；拒答時的伺服器端備援 |
| [`openai_compat.py`](../src/livesub/translation/openai_compat.py) | OpenAI 相容 API（OpenAI、Gemini、DeepSeek、本機 Ollama） |
| [`deepl.py`](../src/livesub/translation/deepl.py) | DeepL（不支援提示詞與術語表） |
| [`passthrough.py`](../src/livesub/translation/passthrough.py) | 不翻譯；也是缺金鑰時的備援（只顯示原文，不會當掉） |
| [`registry.py`](../src/livesub/translation/registry.py) | 依 `translate.engine` 建立對應的翻譯器 |

### 3-6. `core/` 共用工具

| 檔案 | 說明 |

## 4. 重要觀念

| 名詞 | 說明 |
|---|---|
| **WASAPI loopback** | Windows 提供的「錄下喇叭正在播放的聲音」功能，不需要虛擬音效線 |
| **VAD** | Voice Activity Detection，判斷一小段聲音是不是人在說話，用來切句 |
| **ASR** | Automatic Speech Recognition，語音辨識（聲音 → 文字） |
| **定稿／中間結果** | 定稿是一句講完後的最終結果（寫入逐字稿）；中間結果是講到一半的暫時結果（只顯示，會被取代） |
| **幻覺** | Whisper 在靜音或音樂時憑空產生的句子，例如 "Thank you for watching" |
| **語言黏著** | 短句很難判斷語言，信心不足時沿用上一句的語言 |
| **token** | LLM 計費單位，大約是一個字詞片段；翻譯費用 = 輸入 token × 單價 + 輸出 token × 單價 |
| **Protocol（介面）** | 規定「要有哪些方法」，例如所有翻譯器都有 `translate()`，所以可以互相替換 |
| **registry（工廠）** | 依設定值挑出對應的建立函式，主程式不需要知道有哪些服務 |
| **frozen dataclass** | 建立後不能修改的資料物件，多個執行緒同時讀取也安全 |

## 5. 想改某個功能，要看哪裡？

| 想做的事 | 修改位置 |
|---|---|
| 改翻譯規則（語氣、用詞） | `translation/base.py` 的 `SYSTEM_PROMPT` |
| 加一個幻覺過濾句 | `asr/filters.py` 的 `_EXACT_PHRASES` 或 `_CONTAINS_PHRASES` |
| 設定視窗加一個服務選項 | `ui/presets.py` 的 `ASR_PRESETS` 或 `TRANSLATE_PRESETS` |
| 設定視窗加一個欄位 | `ui/settings.py` 對應分頁的 `_build_*`，用 `_spin`／`_check` 等綁定設定鍵 |
| 新增一個設定項目 | `config/schema.py` 加欄位（含預設值），並同步加到 `config.example.toml`（測試會檢查兩者一致） |
| 改字幕外觀或顏色 | `ui/overlay.py` 的 `_Row._paint_colors`、`SubtitleOverlay.paintEvent` |
| 改切句邏輯 | `audio/segmenter.py` 的 `_process_frame` |
| 改逐字稿格式 | `output/transcript.py` 的 `TranscriptWriter.write` |
| 系統匣選單加項目 | `ui/overlay.py` 的 `TrayController.__init__` |

### 新增一個雲端服務（以翻譯服務 `myprovider` 為例）

1. `config/schema.py`：新增 `MyProviderConfig`，掛到 `TranslateConfig.myprovider`，並把 `"myprovider"` 加進 `engine` 的允許值。
2. `translation/myprovider.py`：實作 `translate()`、`warmup()`，以及 `name`、`is_cloud` 兩個屬性。
3. `translation/registry.py`：在 `_BUILDERS` 加一行。
4. `config.example.toml`：加上 `[translate.myprovider]` 區段。
5. （選用）`ui/presets.py`：加一個選項，設定視窗就能直接選。

語音辨識服務也是同樣的步驟，改成 `asr/` 資料夾。

## 6. 測試與檢查

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt   # 第一次
.venv\Scripts\python -m pytest                                # 執行測試
.venv\Scripts\python -m ruff check src tests                  # 檢查程式風格
```

測試不需要音效卡、網路與金鑰（雲端服務都用假的回應代替），改完程式後跑一次就能確認沒有改壞。

| 測試檔 | 測什麼 |
|---|---|
| `test_segmenter.py` | 切句：句子開始／結束、中間結果、強制切斷、斷流 |
| `test_audio_capture.py` | 混音器、三種聲音來源選裝置 |
| `test_pipeline.py` | 管線整體流程、翻譯失敗仍保留原文、中文不送翻譯、中間結果節流 |
| `test_cloud_providers.py` | 語言判斷、雲端辨識與 Claude 翻譯的請求格式、費用、錯誤處理 |
| `test_translate_budget_transcript.py` | OpenAI／DeepL 翻譯、缺金鑰備援、費用帳本、逐字稿格式 |
| `test_filters_glossary_config.py` | 幻覺過濾、術語表、設定檔讀取 |
| `test_settings.py` | 設定視窗存檔（保留註解、只寫變動） |
